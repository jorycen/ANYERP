# 积分礼品收款、库存和毛利（2026-10-28）

## 已确认的经营规则

- 实物礼品关联明确的 ERP 商品及每份出库数量，适用门店复用原配置，不按名称猜测关联。
- 先选领取门店，兑换扣积分并预占该店销售仓库存，核销正式出库；预占到期自动失效，不退积分。实物不再扣独立兑换名额，服务和优惠券保留原名额规则。
- 实收补差款必须等于凭证快照应收金额；收款方式须启用、适用于领取门店、绑定启用 FUND 资金账户。优先使用门店覆盖账户，账户经销商须匹配领取门店或为共享账户。
- 本次核销直接新增 ERP 正式资金账户收入流水，不再仅记录原系统已收款声明。外部支付的实际到账由员工核实，本次未接入在线支付。
- 核销员工销售毛利＝补差款50%；运营毛利＝剩余50%补差款－礼品全部实际出库成本。按分计算，奇数分尾差归运营，确保两者合计等于补差款减成本。纯积分兑换个人销售毛利为0，运营承担全部成本，允许负毛利。
- 非SN成本复用后台剩余采购成本层算法，成本依据必须完整；SN使用实际交付序列号的采购入库成本，缺成本阻止整笔核销，不以零兜底。
- 收款、核销、出库、成本及毛利快照、审计日志在同一事务完成；重复核销不重复处理。库存表保护触发器阻止其他销售、调拨、调整等写入消耗有效预占。
- 公司毛利组成＝销售＋产品＋运营。销售毛利含核销员工份额；运营单独统计，不再重复包含员工份额。按实际核销时间、中国时区日期边界及授权门店统计，员工筛选只看本人份额。
- 经营考核口径与税务财务核实口径继续区分；此处新增的是经营毛利组成，不推定税率或财务核实结果。
- 活动费用、特定激励、手工返款池及退款/冲销新流程暂不在本期开发范围。

## 接口契约

- `GET /api/v1/customer/rewards?store_id=...`：实物 `stock` 为指定适用门店的可兑换份数；未选店为适用门店合计。可兑换份数＝扣除有效预占后的销售仓可用数量÷每份数量，向下取整。
- `GET /api/v1/customer/rewards/:id?store_id=...`：门店列表增加 `available_quantity`；服务/券为null。会员端不自行计算库存。
- `POST /api/v1/customer/rewards/:id/exchange`：实物新增必填 `store_id`，继续传 `expected_points`、`expected_cash`及幂等键；门店写入凭证快照，禁止跨店核销。
- `POST /api/v1/customer-ops/redemptions/preview`：新增 `paymentMethods`、`needSn`、`unitsPerReward`、`requiresInventoryBinding`。
- `POST /api/v1/customer-ops/exchange/:id/redeem`：有补差必传 `cash_received`、`cash_confirmed=true`、`payment_method_id`；SN传 `sn_codes`。优惠券继续要求消费额、适用范围声明及原单号。
- 积分商品维护增加 `product_id`、`units_per_reward`，实物必须明确关联；商品搜索直接复用现有 `/api/v1/product/list?activeOnly=1` 接口，不新增平行商品查询接口。
- 管理端 `POST /api/v1/customer-ops/exchange/:id/bind-stock`：针对未关联库存的历史待核销实物凭证，经管理员人工确认后使用该礼品已配置的商品及数量补建指定门店预占。保留积分和补差价格并记录原快照；不自动批量迁移。
- 财务概览增加 `operationsGrossProfit`、`companyGrossProfit`，`combinedGrossProfit`更新为三端合计。员工、门店、趋势报表复用统一核销销售毛利事件。

## 部署与验收

1. 本地代码完成后，正式环境先执行 `node scripts/migrate-reward-fulfillment.js` 预览，再按发布安排执行 `--apply`。迁移新增字段、预占表及两项库存保护触发器，要求数据库账号具备相应权限。
2. 迁移必须在配套后端启用前完成；不使用缺字段置零或跳过库存保护作为兼容回退。迁移可重复执行，不改历史收款、库存或积分。
3. 更新后端及Web构建；分别在真实 `sdxcx`、`member` 项目编译联调，小程序不上传GitHub。本次未部署或发布，正式数据库仅做只读预览。
4. 管理员先为实物礼品选择ERP商品和每份数量；历史凭证由管理员逐张核对补建预占。
5. 自动验证覆盖并发抢兑、指定门店、库存保护、重复核销、收款及成本错误回滚、过期释放、纯积分负毛利、SN出库、分币尾差、统计权限和原会员回归。正式上线前仍需受控真机收款和跨端对账。
