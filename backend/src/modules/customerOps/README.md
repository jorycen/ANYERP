## 启用步骤

1. 为消费者小程序准备独立 AppID，并在 member/project.config.json 填入。配置该账号的合法请求域名、隐私说明、手机号授权能力；正式发布包含 `pages/points/index` 的版本。
2. 在服务端安全配置中填入 `CUSTOMER_WECHAT_APPID`、`CUSTOMER_WECHAT_SECRET`、`CUSTOMER_TOKEN_SECRET`（至少32字符随机值）。不得把 Secret 放进小程序或 Git。
3. 本模块使用 `CUSTOMER_OPS_ENABLED=true` 开启。先完整配置微信和随机密钥，再开启。没有有效积分规则时，不给订单生成积分领取快照。
4. 发布匹配的后端与 Web 构建后执行 `node scripts/migrate-customer-ops.js --apply`，补入客户运营菜单及 boss/admin 授权；重新登录 ERP 刷新菜单。迁移可重复执行，不使用 force/alter，不删除表。
5. 管理员选择经销商，确认实际订单金额样例，发布积分规则。默认输入100分金额对应1积分，但参与商品必须显式选择；新版本只用于发布后归档的订单，不追补旧单。
6. 创建真实权益：名称、公开HTTPS图片、所需积分、数量、有效天数、适用门店、说明，并上架。空数量为不限，0为不可兑换。
7. 在试点店用真实受控订单跑完小票→消费者微信登录/手机号认领→积分→兑换→员工核销→ERP核对。小程序上传和正式发布由用户明确安排；员工小程序不做远程发布。

微信接入实现使用 jscode2session、getuserphonenumber、getwxacodeunlimit；账号资质、额度和真机跳转效果必须在实际 AppID 配置后验证。公众号由用户配置，可作为另一个小程序入口；不依赖通用公众号菜单保留小票参数。

## 业务约束

- 会员身份按 appid/openid 确认，积分按经销商独立记账。手机号需微信服务端校验，不根据手机号自动合并会员。
- 同销售单唯一绑定；同会员重复领取返回原结果，其他会员拒绝。
- 规则明确商品ID范围，金额基数为商品金额减普通折扣、国补、教育补贴，按原商品金额比例分摊；已抵扣定金是支付构成，不再次增加计分金额。是否符合门店真实补贴口径必须用上线样例确认后发布规则。
- 流水和账户使用 DECIMAL(30,0) 存储整数，避免 mysql2 读取 BIGINT 时的 JS 精度损失。API积分字段为字符串，计算使用 BigInt。
- 兑换时一次扣分并扣数量，核销时不再次扣分。权益快照不随后台编辑改变。
- 原退货完成事务内冲回积分，包括历史手工入库。按原规则和累计退货数量重算剩余积分，重复退货事件不重复冲回。
- 积分不足允许退货形成负余额，负余额阻止新兑换/待用权益核销。已核销事实保留。
- 关闭新功能入口后，已有积分的退货冲回仍继续；不要删除表或回滚掉该接点。
- 权益过期不退积分、不自动补库存；积分本身一期不设过期。
- 核销码、领取码由随机密钥派生且数据库只存摘要；重印保持原码。不要直接轮换 CUSTOMER_TOKEN_SECRET，否则既有小票和核销码会失效；需要轮换时应先实施带版本密钥迁移与受控重新签发。
- 有效领取期当前为归档后90天，权益默认兑换后30天。需要改变这两个运营默认值时先确认业务规则。
- 进程内限流是补充防护；多实例部署建议在网关按IP/用户同步设置额度。数据库唯一约束与行锁不依赖该限流。
