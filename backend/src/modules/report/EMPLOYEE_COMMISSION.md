# 员工毛利汇总与店长分阶段提成

## API

复用 `GET /api/v1/report/employee-profit-summary` 及其 `/export`。
参数继续为 `startDate/endDate/storeId/employeeId/reportRole`；权限与原接口一致。
页面和导出读取同一个 `load`，共用后台 `columns/cells`，不在客户端计算。

## 店长阶段（2026-11-10 用户确认，覆盖月末统一套比例的旧规则）

- 每月从1日起累计全店销售端毛利，产品/运营毛利不参与。
- 以经营流水业务日期和原业务发生时间（北京时间）排序，同刻销售优先、事件ID升序。
- 超过盈亏线前的店长个人毛利按15%，超出后的按25%。
- 跨线订单按跨线前后两部分占该单毛利的比例拆分个人毛利。
- 例：盈亏线100000，已有99900，下一单1000，则该单100按15%、900按25%。
- 退货按原销售单阶段比例冲回；跨月读取原销售月份的盈亏线和冻结流水。
- 退货减少当月累计毛利，后续交易依据减少后的累计值判断阶段。
- 个人经营调整沿原单阶段计提。个人毛利金额、日期和分摊继续沿用员工绩效服务；全店跨线累计沿用财务经营流水业务日期，不改变既有统计日期契约。
- 费用扣减按两个阶段的个人毛利占比分摊，尾差归25%阶段；两阶段毛利存在负数且扣减无法归属时待核实，不猜测费用阶段。
- 先保留两阶段毛利、费用到分，再分别对两阶段扣减后毛利按15%/25%计算并舍入到分，合并个人销售提成。
- 另计全店销售端毛利3%门店提成，石高铭、唐陈为5%；与个人阶段是否可计算独立判断。
- 卢珏、葛宇继续按普通员工规则。

## 数据来源及异常

`managerCommissionTimeline` 读取现有财务经营事件和冻结单据时间，不调用价格或税费重算。
个人分摊复用 `buildEmployeePerformance` 的完整明细；看板默认100条明细限制保持，提成计算显式使用 `allDetails`。
日期只选月中时，阶段仍读取完整月份前序流水；员工及角色筛选不改变全店跨线基数。
跨月报表分月计提后相加，不对合并金额重新套比例。

以下情况返回具体单号和原因，并保留独立可计算的门店提成：原月份盈亏线缺失、原销售阶段无法追溯、跨店归属待核实、冻结销售毛利未知、个人毛利与阶段合计不一致。
禁止使用当前月份盈亏线替代原月份配置，禁止把待核算置零。
本次仅改变报表估算，不写历史订单、毛利快照或审批状态。

## 待核算清单（2026-11-11）

复用 `/employee-profit-summary/export`，增加 `review=1` 下载待核算清单。
可选 `reviewRowKey` 仅限定原报表授权结果中的一行；不能替代员工/角色/门店权限校验。
报表行新增 `issues` 全部阻断原因及 `reviewKey`；顶部批量和行下载均使用已经查询的筛选条件。
产品/运营仅提成待定不生成问题；毛利本身依据缺失时列入问题。
Excel含原因、建议、原单关联商品和SN、定位编号、数据核对指纹、确认填写栏及填写说明。
关联原单商品用于核对，不表示每个商品都有错；SN、编号等按文本导出以保留前导零。
清单已精简为关键问题及填写栏，定位编号/指纹放隐藏的系统校验页；仅商品问题显示商品/SN。
同店同月基数问题合并；历史任期按待确认区间合并，支持北京时间日内交接。

## 跨店及历史店长归属（2026-11-11）

个人销售提成跟人走；每笔店长个人毛利的15%/25%阶段按原销售门店判断。
门店额外3%/5%按原门店业务发生时店长归属，退货和原单调整冲回原业务对应店长。
`T_STORE_MANAGER_ASSIGNMENT` 保存有效任期 `[effective_from,effective_to)`，禁止重叠。
启动迁移只记录观察时刻及以后；不把当前店长倒推到历史。新建门店和店长变更与任职记录同事务保存。
缺失任期显式待确认，并在清单列出待确认区间，不默认为当前经理。个人提成可独立显示；相关门店提成及绩效合计保持待核算。
曾任店长现为店员时个人仍按员工规则，历史门店收益单独叠加；卢珏/葛宇例外保持。
内部销售阶段查询复用经营事件，仅在已冻结退货销售流水明确时允许财务成本待核实，不因此把已知销售流水丢失；普通财务查询仍严格校验原销售。

## 系统上传

- `POST /employee-profit-summary/review-preview`：multipart `file`，最多10MB、500行；只有提成配置管理员可用。
- `POST /employee-profit-summary/review-apply`：同一文件及预览 `token`，20分钟有效且绑定操作人及预览内容。
- 上传须使用新版模板，保留隐藏校验页。系统字段不可修改，仅填写确认值、任期开始/结束和依据。
- 空白不覆盖，明确0有效。过期资料、越权、公式、无效金额及任期重叠均报出行号/原因。
- 同一序号可拆成不同店长的互不重叠任期；精确时间支持 `YYYY-MM-DD HH:mm:ss`，均为北京时间。
- 确认后原子保存基数、历史任期及逐行审计；重复提交不重复处理。单据、采购价格等问题只记录人工意见，不自动修改历史订单。
- 基数保存复用 `commissionConfig.save`，任期保存通过同门店锁校验区间；提交前重新校验问题指纹和当前权限。
- 新模板版本3含服务器签名及原始只读栏位；旧版需重新下载。配置/任期指纹只绑定对应目标，不因无关新销售发生而要求反复下载。
- 个人提成基数按员工和月份读取，不因选择原销售门店、人员已经调店而漏取已有配置。
