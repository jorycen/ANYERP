# 库存报表采购与票据关联

本次仅扩展 `GET /api/v1/report/inventory` 的只读关联；汇总、来源下钻和导出继续共用 `inventoryReport.load`，不修改库存数量、SN采购成本、计价标记或历史业务单据。不扩展服务/虚拟项目排除范围。

## SN来源

先使用实际接收SN关联表和入库明细SN ID；历史无身份ID的记录可使用精确SN编码或实际接收编码数组。已有其他SN身份ID时，不以同编码替代。要求商品相同、入库采购单价与当前SN采购成本按分相同，并在当前SN入库时间及统计时点内找到收货依据。

采购单优先使用入库单的采购申请ID；该ID为空且明确为采购来源时，允许用来源单号精确匹配唯一采购申请号，不做模糊匹配。草稿、待审批、拒绝、撤销采购不作为依据。部分收货优先使用收货时间，必要时使用该SN不可变接收关联时间；历史补建关联表的创建时间不能覆盖原有有效收货时间。

调拨后可沿SN身份追溯原采购来源，但税务测算要求采购所属经销商与当前库存经销商一致。未知或不一致则保留待核实；多个同时间采购来源冲突时不任意取一条。

## 票据依据

在明确采购来源后，优先关联有效已登记发票：结算单的全部应付款必须明确指向同一采购申请，发票所属经销商一致，登记分配金额完整覆盖采购金额，所有相关票种/税率一致，登记时间及发票日期不晚于统计时点。部分覆盖、混合采购结算、票种冲突不能据此推断单件票据。

未满足实际发票完整覆盖时，可继续按采购申请明确约定的票种测算，必须标注“采购申请约定”。只有明确专票和税率才按该税率拆分；“13%含税”不自动等同专票。所有结果仍为预计值，不作为已确认抵扣或正式账面价值。

## 非SN

现有库存台账没有逐件采购批次ID，因此只关联同商品、同门店、同经销商、已收货且不晚于统计时点的采购候选。候选信息不证明当前全部库存来自该笔采购，不默认取最近采购、不伪造FIFO、不据此补算扣税后金额，也不把资源权益剩余数量当作实物批次数量。

## 返回及展示

来源明细新增 `purchaseRequestNo/sourceInboundNo/invoiceNos/invoiceSource/evidenceStatus/evidenceStatusLabel/evidenceReason/sourceCandidateCount/sourceCandidates`。Web来源明细及Excel同时展示采购单号、入库单号、票据来源、发票号码、候选采购及具体待核实原因。元数据版本3，增加已关联数量、非SN采购候选覆盖数量。
