# 财务利润明细、零成本与导出执行任务包（用户已确认开发）

2026-10-29：用户确认营销端与运营端同一口径，统一称运营毛利，并确认开发。以下待确认字样保留为讨论记录，以本段及实施记录为准。

实施记录：兼容扩展原利润接口，view=company 返回三端经营明细；默认返回原财务明细，权限及门店范围不变。概览复用同一后台引擎。导出新增利润明细与毛利汇总，保留原财务表单。复用成本确认及凭据，新增只读逐SN证据识别，不新增核心数据库字段，不批量回填历史零值。新关账冻结经营分配，旧关账缺少运营快照明确待核算。未部署或修改生产业务数据。

## 任务目标

在财务报表利润明细展示销售端、产品端、运营端及公司经营毛利；真实0元成本正常核算，未知成本明确待核算；导出的Excel包含与页面一致的全量利润明细。

## 目标受众 / 使用对象

经销商、财务、采购及有报表权限的经营管理人员；不扩大现有角色或门店访问范围。

## 输入材料与现状

* 财务概览GET /report/finance-overview已有销售、产品、运营和公司合计；此前用户已确认公司毛利由三端合计。
* GET /report/financial-profit-orders及其/export使用financialProfitEngine和financialProfitController，已有销售/退货/调整、政策、费用及关账快照逻辑。当前经营口径合计仅有销售和产品，尚不能视为完整三端合计。
* Web FinancialReports.vue已有利润明细及独立导出入口，当前导出工作表为“销售退货及调整”等，缺明确对应页面的“利润明细”表单；线上实际版本及用户所点下载入口【待核对】，不能断言已部署版本存在这些入口。
* 当前明细grossProfit为不含税销售收入减财务存货成本，与销售考核/经营分配毛利不同；不得把它直接当销售端再加产品端。
* 成本已有cost_status、cost_source、purchasePriceKnown、人工锁定和核实依据。部分取值链仍使用逻辑或或大于0判断，可能覆盖有效0或把默认0误当有效。需逐入口查明已知状态的持久化覆盖情况，不能只修展示。
* 用户本轮用词“营销端”是否等同既有“运营端”【待确认】。推荐统一称运营端；如果是不同部门，不擅自建立第四种毛利。

## 核心变量

业务事件及原单关联、经营日期/归属月、门店与权限、三端毛利来源、产品成本和定价的确认状态、财务成本与经营分配差异、退款冲销、政策收益、关账状态及快照、成本凭据与审核轨迹。

## 最小可行路径

1. 兼容扩展现有财务利润明细及导出API，复用销售、产品结算及会员兑换利润事件服务；概览与明细对相同指标调用同一后台聚合口径，不在前端叠加金额。
2. 新增“销售端毛利、产品端毛利、运营端毛利、公司经营毛利”列及汇总。公司经营毛利等于三端合计；保留原财务商品毛利/税额字段并明确名称，不能把经营分配合计冒称法定报表利润。经营费用只在经营利润层扣减，避免重复扣费。
3. 按业务事件关联归属：同销售单的产品结算关联原单；兑换收入及成本保留兑换单号和核销员工；无销售单的已确认政策等单列可追溯事件，不强挂到无关销售单、不漏计、不把返利全额和内部分配重复累计。退货、冲销和跨月依既有生效规则取负向事件。未知部门金额显示待核算，公司合计不得将其补0后冒充完整。
4. 成本金额与确认状态分离，优先复用并统一已有状态：已确认有价、已确认零成本、待确认/缺失。已确认金额为0时不走备用价格；null、空白、未填、默认0且无依据时待补。正金额同样需要合法有效来源，不能单凭大于0证明已核实。
5. 采购入库、有效库存成本层、拆装成本分配、已售补录和归档快照共同保存成本是否已知及来源；需要人工确认0元时复用现有授权和审计。明确“尚未付款/供应商赠送/录入0元”不自动等于账面成本0。经营回收价值与公司财务成本分摊保留现有区分。
6. 历史0值按证据只读分类；有已批准零成本凭据/真实成本守恒等证据者允许核算，无法区分的旧默认0列待核对。已关账月份保持快照；更正走原核实/调整规则，不直接批量重算历史毛利。
7. 复用现有导出接口，Excel增加明确的“利润明细”“毛利汇总”工作表，明细含业务日期、类型、单号/关联原单、门店、三端毛利、公司经营毛利、成本金额/状态/来源、待核算原因及原财务金额等必要字段。保留现有政策、费用和关账差异工作表。导出取同权限同日期同筛选的全量结果，不能只导当前页；让页面入口名称明确指向利润明细导出。

## 输出格式

后台共享成本与毛利口径调整、兼容API说明、Web展示与Excel文件、必要数据库迁移（仅在已有字段无法保存证据时提出并确认）、相关回归及跨端核对记录、DECISIONS/BUSINESS_RULES/CHANGELOG更新。

## 验收标准

* 相同筛选下每笔公司经营毛利与三端相符，明细汇总、概览和导出一致。单号/状态筛选不能与不受筛选的期间汇总混用。
* 确认0元可计算并显示0.00；确认0元不能被正值兜底替换；未填或旧默认0无凭据不被静默当0。
* 采购、拆装、回收、销售、退货、兑换、独立政策及关账覆盖必要边界；不重复计算原成本、政策收益或内部分配。
* 兑换沿用已确认规则：核销员工取得补差款50%，运营取得其余50%并承担全部礼品成本。其他运营费用/激励不因本轮自动新增记账流程。
* 导出Excel存在“利润明细”工作表，包含全量筛选结果，金额及待核算状态与页面一致，真正缺数据不导出为0。

## 不要做

不将所有历史0值一律视为免费；不将赠送或未付款自动认定为零账面成本；不用1元占位；不按当前商品成本重写归档；不把财务商品毛利与三端经营分配重复累计；不替未确认营销部门另建流程；不改关账保护、审批、门店权限或实收资金。

## 待确认事项

1. “营销端”是否就是现有运营端；如不同，需要说明其收益及成本边界。
2. 是否采用“公司经营毛利＝销售端＋产品端＋运营端；原财务商品毛利单独保留”的展示口径。
3. 是否按上述范围实施；历史数据先分类，不自动批量追认或改关账快照。

## 建议下一步

确认后先明确API统计契约与成本状态来源，再修改后台、接入页面与导出，并用同一批事件核对三端合计、零成本及退货/关账边界。当前仅完成检查和任务包，未修改核心计算或生产数据。

## 方案取舍及财务依据

采用“金额＋确认状态＋来源凭据”的系统设计，比只使用大于0或把所有0放行更可靠；可复用既有状态，实施成本以兼容扩展及回归为主，适合后续增加入口。逐步建立成本来源标识比全量重建成本子账成本低，但历史无依据记录仍需人工核对。

财政部《企业会计准则第1号——存货》规定采购成本还包括相关税费、运输等可归属费用，因此采购价0、付款0不直接等于存货账面成本0；本任务的三态与凭据设计是本项目建议，不是准则规定的数据库结构。来源：https://kjs.mof.gov.cn/zt/kjzzss/kuaijizhunzeshishi/200806/t20080618_46216.htm
